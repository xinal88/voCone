# voCone: Velocity-Obstacle Cone Scalars

A policy observation that reads which of sixteen headings are blocked by a pedestrian within
five seconds at the robot's current speed, added to the AGENT_5 backbone as `AGENT_5_VO`
with the reward unchanged.

## Implementation

`patches/rosnav-rl.patch`, following the time-to-contact template piece by piece:

| Piece | Change |
|---|---|
| data type | `CrowdVelocityObstacleCone` in `observations/utils/types.py`, shape `(16,)`, values in `[0, 1]` |
| generator | `CrowdVelocityObstacleConeGenerator` in `observations/data_sources/generators.py` |
| observation space | `CrowdVelocityObstacleConeSpace` in `spaces/.../environment/crowd_spaces.py`, `Box(0, 1, (16,))` |
| extractor | added to `DRL_VO_ROSNAV_SCALAR_EXTRACTOR.SCALAR_SPACES` |
| agent entry | `AGENT_5_VO(AGENT_5)` in `sb3_policy/paper.py` |
| mirror rule | heading `k` swaps with heading `-k` in `mirror_space_manager.py` (without a rule, `mirror: canonical` raises) |
| generator wiring | `crowd_vo` in the bundled `observations/observations.yaml` |

`patches/Arena-Training.patch` adds `crowd_vo` to `configs/observations/observations.yaml` and `manipulator.yaml`.

Generator, per step:

```
speed     = max(|measured robot velocity|, 0.3 m/s)
heading_k = 2πk/16, counterclockwise from forward, robot frame
v_rel     = v_ped − speed · (cos heading_k, sin heading_k)      # pedestrian velocities are absolute
t         = constant-velocity contact time, contact radius robot + pedestrian, pedestrians within 12 m
sector_k  = max over pedestrians with t < 5 s of (1 − t / 5 s), else 0
```

The contact time reuses `time_to_contact()` from the TTC pipeline, vectorised over all
headings and pedestrians. A pedestrian already in contact blocks every heading.

### Tests

`tests/test_crowd_velocity_obstacle_cone.py` (13 tests) plus the mirror test parametrised over `AGENT_5_VO`:

- empty crowd → all zero; standing pedestrian ahead blocks only the forward heading at the 0.3 m/s floor
- measured speed brings a far pedestrian inside the horizon; oncoming pedestrian blocks ahead harder than behind
- pedestrians beyond 12 m ignored; pedestrian in contact blocks every heading
- **the heading of travel equals the TTC generator's minimum** for forward, left and backward motion
- a scene mirrored across the forward axis mirrors the headings
- space clips and normalises; bundled observations provide `crowd_vo`; the head reads 16 more scalars

Run in a `ros:jazzy` container with Arena message packages stubbed: the full suite gives
728 passed against 714 on the untouched tree, with the same 33 failures and 5 errors on both
(tests that need the real Arena message packages). `ruff check` and `ruff format --check` pass.

## Experiment

Choices the task leaves to the group's backbone run were fixed before any run in
[`experiment/PREREGISTRATION.md`](experiment/PREREGISTRATION.md). They are to be replaced
by the group's backbone config and held-out list if supplied before evaluation.

- **Configs**: [`experiment/configs/`](experiment/configs/), generated by `make_configs.py` from
  `sb_training_config.yaml`; the three arms differ only in agent name and `architecture_name`
  (checked by the script). 4M timesteps, success early stop off, seed 42, DRL-VO heading reward
  `active_heading_direction` on for all arms.
- **Training**: `experiment/start_training.sh setup | prepare | train <ARM> | evaluate`, AGENT_5_VO first.
- **Minimal run** (decisions 7–9): AGENT_5_VO and AGENT_5 at 1M steps with a fixed curriculum schedule,
  evaluated on two held-out splits (crossing family on `hospital_1`, 20 pedestrians):
  `suite_vo_min.yaml`, `contest_vo_min.yaml`, `splits_min.yaml`. AGENT_5_TTC follows.
- **Budget key**: the trainer reads `algorithm.parameters.total_timesteps` (default 10M) and ignores
  `general.n_timesteps`, so the configs set `total_timesteps` explicitly.
- **Evaluation**: one contest with the three arms (`contest_vo_cone.yaml`), one suite per pedestrian
  driver (`suite_vo_heldout_TEMPLATE.yaml`, explicit stage seeds, `max_collisions: 1`, `references: true`).
- **Readout**: `analysis/readout.py` pairs episodes across arms by (stage, episode), reports every delta
  against both controls with a paired bootstrap 95% interval per split, and the chase / drop /
  inconclusive verdict on held-out splits only.

```bash
python analysis/readout.py <run>/combined_metrics.parquet --splits experiment/splits.yaml --out readout
```
